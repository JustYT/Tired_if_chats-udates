# Саммаризатор чатов · публичные подписанные обновления

Этот репозиторий содержит только код выпусков. Базы чатов, пользовательских
настроек, токенов и приватных ключей в нём нет. Источник разработки и исходные
данные остаются отдельно. Новые теги `vX.Y.Z` подписываются Ed25519; приложение
проверяет подпись локально по встроенному публичному ключу **до** замены кода.
Без подписи обновление не устанавливается.
Отпечаток ключа выпуска: `SHA256:uaZatv5XfHCr6Jnfgsliqkndr7RaRD1hOd0WApkH4+g`.

## Первая установка

Получатель использует `chat-summarizer-bootstrap-v2.3.2.tar.gz` из
`JustYT/Tired_if_chats`. Архив не содержит ключа доступа к GitHub. На Linux-ВМ
нужны Python 3.10+, пользовательский systemd, git, ssh-keygen, systemd-run и
уже настроенный Splitty. Установщик проверяет Splitty до создания службы.

```sh
tar -xzf chat-summarizer-bootstrap-v2.3.2.tar.gz
cd chat-summarizer-bootstrap
./install.sh STAFF_LOGIN
curl -fsS http://127.0.0.1:8765/api/health
```

Порт можно передать вторым аргументом. HTTP слушает только `127.0.0.1`, поэтому
с локального компьютера откройте SSH-туннель:

```sh
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 VM_LOGIN@VM_HOST
```

Подключите **свои** токены из shell Стефании командой `connect-remote.py` из
архива. Токены передаются через SSH stdin в оперативное окружение службы и не
сохраняются в файлах; после перезагрузки их нужно импортировать повторно.
Вход в личную подписку Codex выполняется в интерфейсе.

## Обновления

Саммаризатор проверяет новые теги каждые шесть часов и по кнопке. Получение через
HTTPS не требует входа в GitHub и после первого клона скачивает только новые
объекты Git. Тег проверяется по встроенному публичному ключу. Установка
начинается только по кнопке, выполняется с сохранением прежнего каталога кода
и откатом при сбое проверки здоровья службы. SQLite и настройки лежат отдельно.

Прямые команды: `~/.local/opt/chat-studio/update.sh check` и
`~/.local/opt/chat-studio/update.sh apply vX.Y.Z`. Неподписанный тег или тег,
подписанный другим ключом, отклоняется.

## Выпуск новой версии

Приватный ключ подписи находится только у автора выпуска в
`.release-secrets/release_signing_key`; в Git он не добавляется. Перед публикацией
проверяются тесты, состав чистого пакета и отсутствие секретов. Локальный
скрипт `portable/sign-release.sh vX.Y.Z` создаёт и тут же проверяет подписанный
тег в репозитории выпусков. Затем тег публикуется вместе с проверенным кодом.
Если ключ подписи потерян, автоматическую цепочку доверия придётся переносить
новым доверенным bootstrap-архивом; ключ следует хранить в защищённой резервной
копии.
