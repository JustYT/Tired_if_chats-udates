# Саммаризатор чатов · код релиза

Этот репозиторий содержит только код обновлений. Для первой установки
получатель использует исходный архив `chat-summarizer-bootstrap-v2.2.0.tar.gz`,
который владелец передаёт отдельно. Архив содержит этот код и ключ только для
чтения данного закрытого репозитория. Если установку выполняет Codex,
сначала прочитайте `DEPLOY_AGENT.md` внутри исходного архива.

Пакет рассчитан на одного корпоративного пользователя и его собственную Linux-ВМ.
В репозитории только код, статические ресурсы и wheel `websockets`; БД, история,
профили Codex и токены в него не входят. Сервер слушает только `127.0.0.1`.

Требуются Python 3.10+, пользовательский systemd и SSH-доступ.
Для личной подписки Codex дополнительно нужны доверенный установленный
администратором Codex CLI, `/usr/bin/bwrap` и `/usr/bin/prlimit`. Если их нет,
остальные функции работают, а Codex покажет ошибку при попытке входа.

При наличии собственного доступа к этому репозиторию код можно установить
на своей ВМ со **своим** staff-логином напрямую:

```sh
git clone --branch v2.2.2 --depth 1 https://github.com/JustYT/Tired_if_chats-udates.git chat-summarizer-source
cd chat-summarizer-source
./install.sh STAFF_LOGIN
systemctl --user status chat-studio.service
curl -fsS http://127.0.0.1:8765/api/health
```

В обычной схеме получателю доступ GitHub не нужен: он устанавливает из архива,
а встроенный ключ позволяет получать следующие теги обновлений.

Установленный архив поддерживает `~/.local/opt/chat-studio/update.sh check` и
`~/.local/opt/chat-studio/update.sh apply vX.Y.Z`. Исходные данные и токены
не попадают в Git и сохраняются в отдельном каталоге при обновлении.

Если порт 8765 занят, передайте второй аргумент `./install.sh STAFF_LOGIN 8876`.
Код устанавливается в `~/.local/opt/chat-studio`, новая SQLite и профиль Codex —
в `~/.local/share/chat-studio`. Установщик прекращает работу, если уже есть
служба, каталог установки или база: существующие данные не перезаписываются.

Для подключения от своего имени откройте локальный shell Стефании, где доступны
**ваш** `MESSENGER_TOKEN` (и `WIKI_TOKEN`, если нужна публикация в Wiki),
и запустите:

```sh
python3 connect-remote.py --host YOUR_VM_HOST --ssh-user VM_LOGIN --owner STAFF_LOGIN
```

`--owner` должен совпадать с логином, переданным установщику. Команда передаёт
значения по SSH через stdin и импортирует их в оперативное окружение службы,
не сохраняя их в файлах и не печатая. Если токены доступны прямо в shell ВМ,
можно вместо этого запустить `./connect-env.sh`. При наличии
своего `ANTHROPIC_AUTH_TOKEN` можно использовать модель Стефании; для отправки
в бот нужны собственные `CHAT_STUDIO_BOT_TOKEN` и `CHAT_STUDIO_BOT_LOGIN`.
Значения не сохраняются в файлах. После перезагрузки ВМ импорт токенов нужно
повторить. Авторизация Codex выполняется отдельно в веб-интерфейсе и хранится
в индивидуальном каталоге данных.
Список моделей Стефании загружается из корпоративного шлюза после подключения
её токена. В UI можно выбрать модель или оставить вариант по умолчанию.

Перед первым `connect-remote.py` один раз войдите на ВМ обычной командой `ssh`,
чтобы проверить и сохранить её SSH host key. Подключение откажется работать,
если host key неожиданно изменится.

На локальном компьютере откройте SSH-туннель:

```sh
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 VM_LOGIN@YOUR_VM_HOST
```

После этого откройте `http://127.0.0.1:8765/` в браузере. Не выставляйте этот
HTTP-сервис наружу: отдельного веб-входа нет, каждый посетитель считается
владельцем конфигурации службы.

Проверка: `systemctl --user status chat-studio.service` и
`journalctl --user -u chat-studio.service -n 50 --no-pager`.
Для остановки: `systemctl --user stop chat-studio.service`.
Для удаления службы сначала остановите её, затем удалите
`~/.config/systemd/user/chat-studio.service` и выполните
`systemctl --user daemon-reload`. Каталог с SQLite удаляйте только вручную,
если данные действительно больше не нужны.
